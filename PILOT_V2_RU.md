# Новый пилот: найти похожий контракт и проверить, что именно его связывает с другим

30 сентября 2026. Этот документ описывает вспомогательный межплощадочный sanity check после CPI-пилота. Выполнены новый межплощадочный retrieval-эксперимент и качественный разбор девяти пар из четырёх предметных областей.

**Главный результат:** хороший поиск соответствий ещё не определяет отношение выплат. Это теперь показано на внешнем наборе Polymarket–Kalshi и на конкретных правилах, а не на множестве соседних порогов одной серии.

## 1. Что проверяли

Внешний проект [prediction-pipeline](https://github.com/nl2992/prediction-pipeline/blob/f7f652b7ea7c2285fca7c2aa7c02785b11ba9e84/tests/fixtures/endorsed_audit_2026-09-14.json) опубликовал 493 пары реальных контрактов с авторскими метками: 461 `same`, 27 `different`, 5 `unsure`. Есть идентификаторы контрактов и названия родительских событий. Получились два корпуса по 493 рынка, без повторяющихся ID.

Задача первого этапа: **для каждого контракта найти известное соответствие среди 493 контрактов другой площадки**. Метрика — доля запросов, для которых известная пара попала на первое место или в первые пять. Проверены оба направления. Для каждого направления оценены 461 запрос с меткой `same`; остальные рынки остаются среди кандидатов.

Сравнение зафиксировано до inference:

- TF-IDF и MiniLM, без обучения и подбора порогов;
- только дочерний заголовок против того же заголовка вместе с родительским событием;
- одинаковый состав кандидатов и одинаковый k;
- без цен, разрешившихся исходов, меток и пояснений автора во входах модели.

**Особенность источника:** 436 из 493 Polymarket-заголовков в этом файле содержат не более трёх слов. Часто это название исхода вроде команды или кандидата. Поэтому эксперимент проверяет сохранение контекста при такой схеме загрузки данных; он не доказывает, что полный `question` из Gamma обычно неполон.

## 2. Полученный результат

Доля известных соответствий, найденных на первом месте:

| Метод | Вход | Polymarket → Kalshi | Kalshi → Polymarket |
|---|---|---:|---:|
| TF-IDF | Дочерний заголовок | 400/461 — 86,8% | 403/461 — 87,4% |
| MiniLM | Дочерний заголовок | 395/461 — 85,7% | 277/461 — 60,1% |
| TF-IDF | Событие + заголовок | 457/461 — 99,1% | 455/461 — 98,7% |
| MiniLM | Событие + заголовок | 456/461 — 98,9% | 454/461 — 98,5% |

Добавление контекста исправило 178 ошибок ранжирования MiniLM в направлении Kalshi → Polymarket и добавило одну новую. Усреднение по событиям сохраняет эффект: 54,9% → 98,3%. Например, короткое название **Good Afternoon** без контекста было на 21-м месте, с контекстом события — на первом. Точные записи и ещё два примера находятся в [независимой проверке расчётов](redesign/retrieval/REVIEW_RU.md).

**Вывод для реализации:** сначала сохранять родительское событие и проверять простой TF-IDF. Здесь контекст важнее замены лексического метода нейросетью: TF-IDF с контекстом немного лучше MiniLM на первом месте. Этот эксперимент не обосновывает покупку более дорогой модели.

У MiniLM с контекстом все 461 известное соответствие попадают в top-5 в обоих направлениях. Но это **полнота восстановления известных ссылок в небольшом, предварительно отобранном корпусе**, а не качество на всём рынке. Авторская разметка не является независимо подтверждённым human gold; неизвестные перекрёстные пары не объявлялись отрицательными. [Аудит данных и происхождения меток](redesign/datasets/DATASET_AUDIT_RU.md).

## 3. Почему второй этап действительно нужен

Из 27 пар, которые внешний автор обозначил как `different`, MiniLM с контекстом в направлении Kalshi → Polymarket ставит **24 на первое место и все 27 в top-5**. Поиск находит близкий объект; он не обязан отсеивать вложенность, несовместимость или разные условия. Присвоить всем найденным парам эквивалентность было бы ошибкой постановки.

Это задаёт понятный вход второго этапа: «Пара найдена. Какую именно связь разрешают её правила?» Подготовлены девять исследовательских карточек:

| Область | Пара / механизм | Что проверяем по условиям |
|---|---|---|
| Политика | Объявленная отставка → уход с поста | Оба текста учитывают объявление; в общей модели согласованных сообщений получаем условное следование |
| Политика | Импичмент / уход с поста | По сохранённым текстам возможны все четыре бинарных сочетания; строгой логической связи нет |
| Политика | «Trump out» на двух площадках | Kalshi имеет явную ветвь выплаты по последней цене; общая бинарная модель неполна |
| Макроэкономика | Recession по GDP / по NBER | Одинаковое слово скрывает разные определения и время события |
| Макроэкономика | Наличие повышения Fed / ровно одно повышение | Различаются окно наблюдения и единица счёта: 26–50 bp считаются двумя hikes |
| Игры | GTA VI выпущена / выпуск перенесён | Условие переноса включает объявление, поэтому нельзя автоматически взять отрицание фактического выпуска |
| Игры | GTA VI / GTA Online | Разные продукты и даты; отдельно распространяемый multiplayer допускается правилами Kalshi |
| Спорт | World Series / победа своей лиги | Кандидат на вложенность; требуется проверить формат турнира и исключения |
| Спорт | World Series / победа другой команды в лиге | Кандидат на несовместимость; в индексированной копии правил есть несуществующая дата November 31 |

Наиболее удобный пример для разговора — **импичмент и уход**: импичмент без ухода, уход без импичмента, оба события и ни одного события совместимы с выбранными текстовыми условиями. Это хорошо объясняет различие между политически связанными событиями и логическим следованием.

Наиболее существенный пример для исследования — **межплощадочный Trump out**. [Официальный Kalshi API](https://external-api.kalshi.com/trade-api/v2/markets/KXTRUMPOUT27-27-DJT) явно предусматривает особую выплату при уходе вследствие смерти: последнюю цену либо определяемое комитетом распределение. Бинарная таблица Да/Нет не описывает весь контракт. Этот вывод опирается на конкретный пункт, а не на общую оговорку «правила могут отличаться».

Карточки — **качественный AI-assisted разбор, не размеченный тест точности**. У них разные уровни источников: официальный Kalshi API, публичная копия `rules_raw` в ClearMarket и индексированные страницы Polymarket. Прямой Gamma-доступ остаётся недоступен; текущая редакция копий не подтверждена. Извлечённые цены и фактические исходы в анализ текста не включались. [Политические карточки](redesign/cards/README_RU.md) · [остальные шесть карточек](redesign/discovery/official_probe/PAIR_CARDS.md).

## 4. Какой научный эксперимент из этого следует

**Гипотеза:** при одинаковых кандидатах и одинаковых полных текстах LLM, которая извлекает проверяемые поля, рассматривает контрсценарий и допускает отказ, делает меньше ложных заявлений о строгих связях, чем прямое присвоение типа отношения.

Для проверки потребуется новый набор пар с независимой разметкой, разделённый по семействам событий. Сравнить прямую классификацию, структурирование и структурирование с контрсценарием; уравнять бюджет вызовов. Отдельно измерять эффект добавления полных правил: дополнительную информацию нельзя приписывать пользе формата промпта. Основная метрика — точность заявленных связей при одинаковой доле ответов; пропуски поиска оцениваются отдельно.

Само добавление контекста события и двухступенчатый поиск не заявляются как научная новизна. Пилот уже обосновывает выбор сильного простого baseline, показывает конкретную границу его применимости и даёт материал для постановки исследования резолюшена.

## 5. Что открыть и как повторить

Для объяснения результата достаточно [выполненного notebook](notebooks/pilot_v2.ipynb) и [текущего исследовательского обзора](README.md). Notebook читает готовые результаты; скачивать модели для просмотра не нужно.

Полный пересчёт из корня проекта, после установки зависимостей из `pilot/requirements.txt` и `extension/nlp/requirements.txt`:

```bash
python extension/nlp/download_models.py
python redesign/run_retrieval.py
```

Использованы закреплённая версия MiniLM, CPU, seed=0; усечённых входов нет. Все численные результаты проверены вторым проходом по сохранённым эмбеддингам и TF-IDF без повторного модельного запуска. Прежний пилот сохранён как история работы и не используется для оценки нового.
