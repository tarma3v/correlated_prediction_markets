## Самостоятельная критика: что именно стоит проверять

### 1. Центральный объект — множества возможных выплат, а не совпадение единственной реализации

Пример собственного построения: A = «показатель выше 5», B = «тот же показатель выше 3», одинаковые источник, время и единицы. A⇒B. Значение показателя 4 даёт (A,B)=(0,1), поэтому сравнение same/different сочтёт корректную импликацию ошибкой. Различие реализаций не опровергает импликацию; опровергает только (1,0).

Другой пример: A/B — победа двух разных кандидатов при единственном победителе. Запрещена (1,1); (0,0) разрешена, когда выиграл третий. Взаимоисключение нельзя оценивать как обязательное противоположное разрешение.

Для независимых Bernoulli A,B вероятность совпадения = pA*pB+(1−pA)*(1−pB). При pA=pB=.1 она равна .82. Значит, высокая accuracy совпадений может возникать без найденной связи. Это самостоятельное математическое объяснение, не дополнительный результат статьи.

Уровни надо разделять: (i) точные ограничения выплат по спецификации, (ii) экономическая зависимость вероятностей, (iii) корреляция временных рядов цен. Из текста можно исследовать (i) и предлагать гипотезы (ii); (iii) требует отдельного статистического дизайна. Под общей вероятностной мерой точная импликация даёт Cov(1A,1B)=pA*(1−pB)≥0, а исключение Cov=−pA*pB≤0. Но это не утверждение о корреляции ценовых приращений.

### 2. Более сильная проблема signed balance: неверный критерий для допустимой логики исключений

Пусть три бинарных рынка означают победу каждого из трёх кандидатов на одних выборах. Каждая пара корректно взаимоисключается: A+B≤1, B+C≤1, A+C≤1. Граф из трёх отрицательных рёбер имеет frustration не меньше 1/3, потому что невозможно xA*xB=xB*xC=xA*xC=−1. Однако логические ограничения полностью совместимы; например, (A,B,C)=(1,0,0) допустимо.

Следовательно, низкая signed frustration не является общей проверкой корректности графа отношений контрактов. Она проверяет специальную модель одинаковых/противоположных меток. Отношения типа исключения и импликации должны становиться соответствующими SAT/ILP-ограничениями. Более того, любой подписанный лес имеет нулевую frustration независимо от истинности его семантических связей; весь положительный граф тоже всегда имеет нулевую frustration. Для доказательства пользы graph module нужны matched-density/degree/cycle baselines, semantic precision, доля удалённых правильных рёбер и unsatisfiable cores.

Не следует утверждать, будто авторы не понимают proxy-ограничение: v2 прямо обсуждает construct validity. Наш вклад — конкретный контрпример с допустимым графом взаимоисключений и операциональная замена проверки.

### 3. Сравнение должно удерживать фиксированными retrieval, coverage, budget и целевой label

Система, выбирающая редкие простые пары, может выглядеть лучше плотного классификатора. Тест на пересечении выбранных пар полезен, но не измеряет recall и обусловлен решением обоих методов выбирать пару. Нужен общий, независимо размеченный candidate pool, precision–coverage, cost–quality и типизированные confusion matrices. Отдельно измерять retrieval Recall@K; потеря пары до LLM не исправляется качеством LLM.

Топический clustering полезен для затрат, но жесткое ограничение «только внутри кластера» не гарантирует полноту. Для строгой логики можно сравнить union lexical+dense+entity/date retrieval со strict clustering и проверить связанные пары, которые теряются на межкластерной границе. Нулевой результат по этому тесту тоже полезен.

Не следует называть «новизной» простое соединение NLI и LLM: это предложено уже в v2 и является исходной постановкой исследования.

### 4. Нельзя доказывать арбитраж прибылью из отношения общего направления

Из «A и B экономически положительно связаны» не следует pA=pB. Например, зависимость может быть pB=.2+.5*pA, иметь лаги и меняться по режимам. Поэтому перенос pA на B — стратегия со специфической модельной гипотезой, а не следствие положительного знака.

Даже у точной импликации A⇒B экономическое ограничение — pA≤pB при общей согласованной вероятностной оценке; точное равенство требуется только для эквивалентности. Для исключения pA+pB≤1, для дополнения =1. Наблюдаемое нарушение цен надо проверять на исполнимых сторонах стакана, сдержках и доступных позициях. Это вторичная прикладная оценка, не основная метрика качества relation extraction.

В backtest требуют внимания: выбор параметров по тестируемому периоду, нерегулярные/устаревшие котировки, общий рыночный риск, воспроизводимость дат вычисления связей, несколько ставок на один underlying, fee-rounding/multipliers. Не надо переносить все ограничения v1 на v2: вторая версия заметно улучшает дизайн и прямо оговаривает приближённые комиссии.

### 5. Resolution clauses — источник перспективной новизны

Предлагаемый объект каждого рынка: proposition, entity, threshold/comparator, time window/timezone, measurement source, revision policy, cancellation/dispute rule, payout domain и evidence spans. Поля должны иметь unknown. Нельзя догадкой дополнять отсутствующий источник или считать одинаковыми event date и deadline публикации.

Особенно интересны семантически близкие cross-platform пары с несовпадающими оракулами/правилами. Название может совпадать, но различие official preliminary/final estimate, intraday/closing price, deadline/timezone или отмены делает эквивалентность необоснованной. Это нужно проверять реальными документированными кейсами; искусственные изменения пригодны только для диагностического challenge set.

## Представление через допустимые миры: предложение для эксперимента

Пусть S⊆{00,01,10,11} — точно установленное множество допустимых сочетаний бинарных выплат, а не наблюдённые исходы или состояния без доказанного запрета. Таблица ниже предполагает известное S. При неполных правилах хранить для каждого состояния forbidden / possible_witness / unknown, как в protocol/annotation_guide.md; unknown нельзя включать в S как доказанно возможное. Вместо forced same/different возвращать статусы состояний, тип, evidence и abstain.

| Тип | Допустимые сочетания | Ограничение |
|---|---|---|
| equivalence | 00,11 | A=B |
| A implies B | 00,01,11 | A≤B |
| B implies A | 00,10,11 | B≤A |
| complement | 01,10 | A+B=1 |
| mutually exclusive | 00,01,10 | A+B≤1 |
| jointly exhaustive | 01,10,11 | A+B≥1 |
| no_hard_relation (все четыре состояния имеют свидетели) | 00,01,10,11 | нет нетривиального бинарного логического ограничения |

Это не заявление об изобретении новой логики: такая типология родственна известной natural-logic relation algebra. Исследовательская новизна, если подтвердится обзором и экспериментом, — её resolution-aware применение и проверка на рыночных данных. Unknown/ambiguous — эпистемический статус, его нельзя смешивать с доказанной независимостью. Для nonbinary/refund payout нужна расширенная область выплат, иначе abstain; для гарантированно истинного/ложного события могут потребоваться дополнительные вырожденные отношения.

Практическое извлечение: задавать четыре вопроса о возможности миров; для каждой невозможности требовать минимальные цитаты из правил и логический аргумент; deterministic checker проверяет даты, числа и согласованность вывода. Наличие evidence span само по себе не гарантирует entailment.

## Фальсифицируемые гипотезы и варианты проверки

1. **H1: structured resolution fields повышают precision строгих связей.** Сравнить title-only, title+raw-rules, structured-rules с одним backbone, одинаковым retrieval и бюджетом. Primary: macro-F1/precision при фиксированной coverage; hard slice = несовпадение источника/времени. H1 опровергается, если CI разницы включает practically meaningful отрицательный эффект/нет ожидаемого улучшения. Порог практической значимости пререгистрировать после оценки мощности, не выбирать по результату.
2. **H2: допустимые миры уменьшают complement/exclusion и equivalence/implication путаницу.** Одинаковая модель: plain multiclass vs four-world structured judgment; paired family bootstrap; измерить forbidden-cell precision/recall, macro-F1, abstention. Не сравнивать только overall same/different accuracy.
3. **H3: checker уменьшает ложные строгие связи при одинаковой coverage.** Ablation raw LLM, LLM+counterexample, LLM+typed constraints. Измерить false-discovery rate, сохранение правильных рёбер, число исправлений и стоимость. Граф может быть satisfiable и неверен: это обязательная оговорка.
4. **H4: independent pair assessment повышает устойчивость к порядку/batch при сравнимом качестве.** Несколько перестановок фиксированного пула, одинаковое число inference-вызовов; edge inclusion Jaccard, sign/type stability, semantic F1, cost. Простая стабильность выдачи всех пар не успех.
5. **H5: cross-platform transfer ухудшается преимущественно из-за clauses, а не названий.** Train/dev на одной площадке/семействах, test на другой + unseen families; отдельная ручная разметка oracle/date/method mismatch. Сравнить размер gap при title-only и full-rules. Это гипотеза, не уже установленный факт.

## Минимальный исследовательский дизайн

- 200–400 вручную размеченных пар из нескольких тематик: mix real positives, random negatives и hard near-duplicates; два аннотатора хотя бы для 20–30% pilot, adjudication и explicit uncertain.
- Не утверждать population prevalence из обогащённой выборки; отдельный random retrieval slice нужен для precision на рабочем потоке.
- Разделять train/dev/test по underlying event/семейству, а не случайной парой; общий market в нескольких сплитах создаёт leakage. Temporal holdout и будущие snapshots усиливают вывод.
- Сначала BM25/TF-IDF, dense, bidirectional NLI, простой LLM; затем только одно ключевое улучшение. Оценка прототипа должна включать разбор ошибок отдельно от финансового результата.
- Результаты разметки: agreement по классам, confusion complement/exclusion и equality/implication, missing-source errors, evidence fidelity. Итоговые метрики: retrieval Recall@K, relation macro-F1, strict precision@coverage, family-bootstrap CI, cost/latency.
- При редких labels не обещать статистическую значимость из малого pilot; использовать пилот для мощности основного исследования.

## Выполненная аналитическая проверка (не эксперимент на моделях)

Полным перебором 8 бинарных состояний трёх переменных в Python подтверждено: отрицательный треугольник требует минимум 1 несогласованного знакового ребра из 3; при типизированном взаимном исключении допустимы 000, 001, 010, 100. Если дополнительно требовать одного победителя, остаются три состояния. При их равных вероятностях каждая пара индикаторов имеет correlation = −1/2: допустима тройка взаимных отрицательных корреляций. Следовательно, структурный баланс не является необходимым условием даже для корректной матрицы корреляций. Это маленький воспроизводимый контрпример, а не эмпирическая оценка NLP-пайплайна.
