## Защищаемый вклад

**Рабочее название:** «Selective resolution entailment: обнаружение строгих отношений между контрактами с проверяемыми основаниями и отказом при недостаточных правилах».

Исследовательский вопрос: снижает ли структурированное сопоставление условий резолюции число ложных строгих связей на трудных, внешне почти одинаковых контрактах по сравнению с прямым NLI/LLM при одинаковом coverage и бюджете?

Предлагаемый вклад — проверяемая надежность и диагностика ошибок, а не сама двухступенчатая архитектура. Ожидаемые артефакты:

1. Аннотированный набор пар с правилами, их версией и provenance; отдельные срезы по источнику, времени, числам, исключениям и отмене события. Два независимых аннотатора и adjudication; размечается основание, а не только класс.
2. Retrieval с измеренным Recall@k и бюджетом; gold должен включать пропущенные retrieval пары. Разбивать train/test по событию, семейству шаблонов и времени, иначе почти одинаковые пороговые рынки утекут в тест.
3. Сравнение: title similarity → description similarity → bidirectional NLI → direct LLM → extraction+reasoner → тот же метод с counterexample/abstention. Для каждой абляции одинаковый пул кандидатов и одинаковые поля.
4. Основные метрики: precision строгих связей, per-class recall/F1, risk–coverage, доля неверного entailment, стоимость на подтвержденную связь. Bootstrap по event clusters, не по зависимым парам.

Гипотезы нужно записать до просмотра закрытого теста. Например: (H1) полные правила уменьшают false equivalence относительно titles; (H2) числовой и временной reasoner улучшает надежность именно соответствующих срезов; (H3) counterexample+UNKNOWN уменьшает риск при фиксированном coverage. Отрицательный результат по H2/H3 тоже научно полезен, если протокол честный.

## Два уточнения к прямому конкуренту

В [§4.2 и Appendix E/F Semantic Non-Fungibility](https://arxiv.org/html/2601.01706v1) строгая формализация через все состояния соседствует с прагматическим решением по реалистичным сценариям и соглашениям по умолчанию. Это различие стандарта доказательности — хорошая проверяемая граница нового исследования. Данные в §4.1 обещаны после публикации; наличие открытого скачивания в этой проверке не подтверждено.

Самостоятельная алгебраическая проверка §3.6: для A⊆B портфель YES(B)+NO(A) выплачивает 1+X_B−X_A. Он гарантирует **не меньше** единицы, но при B∧¬A выплата равна двум. Поэтому это нижняя граница выплаты, не постоянная единичная выплата. Такую небольшую проверку стоит показать на обсуждении, без обесценивания всей работы.

## Новые источники сентября 2026: прочитан abstract, не полная оценка

- Nechepurenko, [From Public Evidence to Contractual Outcome: First and Stable Decidability on Kalshi](https://arxiv.org/abs/2609.16642), 15.09.2026. В описанном историческом сборе не восстановлены необходимые исторические версии правил и официальные release objects; автор явно не трактует это как отсутствие decidability. Практический вывод: сохранять правила и источники prospectively, не считать текущий текст достоверной исторической версией.
- Nechepurenko, [Resolution Is Not Settlement, Part II](https://arxiv.org/abs/2609.15373), 14.09.2026. Разделяет Oracle result, protocol payout и фактический redemption; в exact-linked cohort сообщает 410 fifty-fifty payout vectors. Значит, строго бинарный анализ следует объявить ограничением выборки; отмена/нестандартная выплата требуют отдельного состояния либо исключения с отчетом о числе исключенных контрактов.

Эти источники подтверждают актуальность учета provenance/версий и payout semantics, но пока не заменяют проверку собственной доступности данных и первичных правил конкретных площадок.
