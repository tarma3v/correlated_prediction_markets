# Вспомогательная диагностика локальных LLM

Этот опыт по заголовкам не оценивает основную задачу типизации договорных отношений. Он не воспроизводит модель Gemini 3.1 Pro Preview из [референса v2](https://arxiv.org/html/2512.02436v2). Эффекты модели, размера, квантизации, prompt и формата здесь не разделены абляциями.

Две модели запущены локально, без дообучения: Qwen3-4B-Instruct-2507 и Llama-3.2-3B-Instruct. Использованы MLX community conversions с квантизацией 4 bit. Точные repository IDs, revisions и SHA-256 файлов — в [models.json](models.json). Сравнение относится именно к этим конфигурациям, а не ко всем версиям Qwen/Llama или к облачным LLM.

## Данные и границы результата

В [inputs.json](inputs.json) сохранены одинаковые 73 запроса для обеих моделей, включая system prompt и JSON-схему. [План](../protocol.md) зафиксирован до новых LLM-ответов, но после просмотра прежних baseline: это разведочный эксперимент.

* **64 пары описаний:** 32 авторских `same`, все 27 `different` и 5 `unsure`. Модель видит только event title и market title обеих сторон. Метки и авторские объяснения скрыты. Согласие считается на 59 определённых метках; `unknown` и ошибки остаются в знаменателе. Это не проверка эквивалентности выплат по полным правилам.
* **9 пар с текстами правил:** все доступные исходные поля и ограничения источников, без прежних AI-выводов. Здесь нет независимой эталонной разметки. Публикуются решения, цитаты, контрпримеры и пропуски; accuracy не вычисляется.

JSON разбирается без исправления, обрезки обёрток и выбора удачных повторов. Ограничение вывода — 256/1024 новых токена для двух задач; превышение лимита сохраняется как ошибка. Проверка цитаты означает только наличие точной подстроки, а не достаточность доказательства.

## Фактические результаты

Оба прогона завершены: по 73 первичных ответа, без обрезки входов и без исправления ответов. Runtime Qwen — 445 секунд, Llama — 266 секунд после загрузки модели.

| Показатель | Qwen3-4B | Llama-3.2-3B |
|---|---:|---:|
| Согласие с 59 определёнными авторскими метками | 29/59 (49.2%) | 19/59 (32.2%) |
| Покрытие решениями exact/not_exact на этих 59 | 52/59 | 43/59 |
| Согласие среди принятых решений | 29/52 | 19/43 |
| Согласие в классе same | 5/32 | 0/32 |
| Согласие в классе different | 24/27 | 19/27 |
| Balanced agreement | 52.3% | 35.2% |
| JSON соответствует схеме, все задания | 73/73 | 47/73 |
| Ответ также прошёл проверку ID и завершения | 66/73 | 47/73 |
| Цитата присутствует как точная подстрока | 230/253 | 172/186 |

У Qwen семь ошибок копирования ID. У Llama — 24 ошибки JSON parsing и два нарушения схемы; все девять ответов по правилам не прошли строгий парсер. Ошибки сохранены в полном знаменателе. Счётчик цитат использует только schema-valid JSON, поэтому покрытия у моделей разные. Наличие подстроки не проверяет смысл.

Контроль «всегда same» даёт 32/59 обычного и 50% balanced agreement; «всегда different» — 27/59 и 50%. Оба LLM-прогона сильно смещены к `not_exact_match`. Эти конфигурации не стали надёжным фильтром; это не опровержение метода LLM и не изолированный эффект размера модели. Строгие ошибки JSON не измеряют финансовую семантику. Полные confusion tables, пять авторских `unsure` и девять rule-кейсов сохранены в summary каждой модели.

Независимый пересчёт и качественный AI-разбор: [AUDIT.md](AUDIT.md). Например, Qwen принимает outcome label за утверждение о наступившем исходе; в разборе правил встречается вывод, противоречащий процитированному условию. Это наблюдения по конкретным ответам, не независимая экспертная разметка.

**Следующий эксперимент:** заранее сравнить исходный prompt с явным восстановлением утверждения из event title + outcome label; связывать ID вне генерируемого текста; отдельно оценивать надёжность формата и семантическую проверку цитат. Для выводов об улучшении нужен новый набор с независимой разметкой. Эти улучшения в текущих числах не применены.

## Воспроизведение

Фактическая среда — Python 3.11, macOS ARM, Apple Metal. Этот runner требует Apple Silicon; запуск под Linux не проверен и MLX/Metal-команда для него не подходит. Чтение JSON-результатов не требует MLX.

Из корня репозитория:

```bash
python3.11 -m venv .venv-llm
.venv-llm/bin/pip install -r comparison/requirements-llm.txt
.venv-llm/bin/python comparison/download_llms.py
.venv-llm/bin/python comparison/reproduce_llms.py --model qwen3_4b --output-dir comparison/reruns/local
.venv-llm/bin/python comparison/reproduce_llms.py --model llama32_3b --output-dir comparison/reruns/local
```

Веса загружаются в исключённый из Git `tmp/llm_cache`; требуется несколько GB диска. Downloader обновляет только реестр загрузки `models.json`; сохранённые предсказания не перезаписываются. Для очередного повтора выберите новый output-dir. Seed, greedy decoding и revisions закреплены; численная идентичность между другими версиями среды не гарантируется.

В каждой папке модели: `predictions.jsonl` — все первичные ответы, `summary.json` — агрегаты, `run_manifest.json` — среда, время и hashes. Для Qwen отдельно сохранён `startup_failure.json`: первый запуск остановился до inference из-за пропущенного chat template; после исправления загрузки модель запущена заново, без повторного выбора ответов.
