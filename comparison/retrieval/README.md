# Вспомогательный retrieval sanity check

Расчёт выполнен локально 29 сентября 2026 UTC (30 сентября по UTC+4), CPU float32, без обучения. Основной вход — `event_title + "\n" + title`; вспомогательный — один `title`. Это поиск похожих рынков по короткому описанию, а не сравнение полных правил резолва.

Кандидатный пул одинаков для всех моделей: 493 Polymarket × 493 Kalshi, без фильтрации. Оценка использует 461 известную пару с авторской меткой `same` из ранее зафиксированного внешнего аудита. Для каждого запроса есть одна такая пара, поэтому query hit rate и known-link recall здесь совпадают. Это не независимая исчерпывающая разметка и не оценка полноты на всей площадке. Пул сформирован из уже сопоставленных автором пар и существенно проще открытого поиска. Нельзя считать остальные комбинации отрицательными примерами.

В 285/461 положительных пар заголовок Polymarket буквально входит в заголовок Kalshi после `.lower()` (278/461 без изменения регистра). Пул уже отфильтрован внешним matcher. Эти результаты — sanity check, не различающий benchmark и не заглавный результат исследования. [Проверка смещения](../../research/validated_findings.md).

## Результаты

Ниже число найденных известных связей; знаменатель каждой ячейки — 461. Порядок чисел: Polymarket → Kalshi / Kalshi → Polymarket.

| Модель | Вход | @1 | @3 | @5 | @10 |
|---|---|---:|---:|---:|---:|
| E5-small-v2 | событие + заголовок | 458 / 453 | 460 / 461 | 461 / 461 | 461 / 461 |
| BGE-small-en-v1.5 | событие + заголовок | 455 / 453 | 461 / 461 | 461 / 461 | 461 / 461 |
| E5-small-v2 | заголовок | 405 / 373 | 455 / 446 | 458 / 455 | 461 / 458 |
| BGE-small-en-v1.5 | заголовок | 403 / 371 | 454 / 448 | 458 / 456 | 460 / 461 |

Для сопоставления ранее выполненные варианты с контекстом события: TF–IDF @1 = 457 / 455, @5 = 460 / 461; MiniLM @1 = 456 / 454, @5 = 461 / 461. Эти цифры считаны из неизменённого `redesign/retrieval/summary.json`. E5 и BGE не дают устойчивого превосходства над обоими базовыми методами по двум направлениям. Разница в несколько пар сама по себе не доказывает статистическую значимость.

Новые модели воспроизводят важное ограничение первого этапа: из 27 пар с авторской меткой `different` в top‑1 попадают 24 / 23 у E5 и 21 / 23 у BGE при входе «событие + заголовок». Все пять `unsure` попадают в top‑1 у обеих моделей в обоих направлениях. Эти счётчики не являются precision или false-positive rate: это неполная специальная выборка размеченных пар. Они показывают, что retrieval не заменяет проверку резолюшена.

Event-macro query hit rate также сохранён: 254 группы названий событий со стороны Polymarket и 252 со стороны Kalshi. Не следует объединять направления в одну оценку без явного описания агрегирования.

## Точная конфигурация

- [E5-small-v2, официальная карточка закреплённой версии](https://huggingface.co/intfloat/e5-small-v2/blob/ffb93f3bd4047442299a41ebb6fa998a38507c52/README.md): `query: ` на обеих сторонах, masked mean pooling, L2-нормализация. Авторы рекомендуют этот префикс для симметричного semantic similarity / paraphrase retrieval. Схема `query:` / `passage:` предназначена для асимметричного поиска запрос → документ и здесь не использована.
- [BGE-small-en-v1.5, официальная карточка закреплённой версии](https://huggingface.co/BAAI/bge-small-en-v1.5/blob/5c38ec7c405ec4b44b94cc5a9bb96e735b38267a/README.md): без инструкции, CLS pooling, L2-нормализация. Карточка рекомендует добавлять инструкцию короткому запросу при поиске длинных документов; для данного сопоставления двух коротких описаний она не добавлена.
- Размер векторов 384, cosine через нормализованный dot product, стабильная сортировка по исходному порядку при равных оценках. Обратное направление использует транспонированную матрицу симметричных эмбеддингов.
- Лимит 512 токенов, **обрезаний 0**; максимальный вход с префиксом и служебными токенами — 55 токенов (E5), 53 (BGE). Скрипт прекращает работу, если вход превышает лимит, и не выполняет молчаливое усечение.
- PyTorch 2.0.1, Transformers 4.44.2, CPU, 4 потока, batch 32, seed 0, `eval()` и `inference_mode()`. Веса загружены в safetensors без remote code. Фактический локальный расчёт четырёх вариантов занял 19.16 с; скачивание моделей выполнено до него и не включено в это время. Скорость зависит от оборудования.

`run_manifest.json` содержит immutable revision SHA, SHA256 всех файлов моделей, скрипта, входов и результатов, версии зависимостей и timestamps. Официальные карточки, конфиги, tokenizer и веса загружаются по закреплённым revisions в исключённый из Git `tmp/hf_cache/`; URL и fingerprints остаются в manifest. Набор весов проверен по SHA256, полученному из HF metadata. Старые результаты не изменены.

## Файлы и воспроизведение

Полные входные копии корпуса исключены из Git из-за неустановленной лицензии; восстановление: `python3 scripts/fetch_reference_inputs.py`.

Из корня репозитория создайте отдельное окружение Python 3.11:

```bash
python3.11 -m venv .venv-retrieval
.venv-retrieval/bin/pip install -r comparison/retrieval/requirements.txt
```

Проверка и post-hoc анализ читают готовые результаты, не загружают модели и не запускают inference. Они пересохраняют только собственные отчёты `verification.json` и `error_overlap.json`:

```bash
.venv-retrieval/bin/python comparison/retrieval/verify_outputs.py
.venv-retrieval/bin/python comparison/retrieval/analyze_error_overlap.py
```

**`run_embedding_models.py` перезаписывает результаты и manifest в `comparison/retrieval/`. Для повторного inference используйте отдельную рабочую копию репозитория**, создав в ней окружение указанными выше командами. При первом запуске модели скачиваются по закреплённым SHA в `tmp/hf_cache/`:

```bash
.venv-retrieval/bin/python comparison/run_embedding_models.py
```

Только после первичной загрузки всех закреплённых файлов в этой рабочей копии доступен запуск без сети:

```bash
.venv-retrieval/bin/python comparison/run_embedding_models.py --offline
```

Опубликованный расчёт выполнен на macOS CPU. Фактический запуск и установка этого окружения на Linux **не проверены**; платформенные версии зависимостей могут потребовать отдельной проверки.

- `summary.json` — все @1/3/5/10, micro и event-macro.
- `results.json` — необязательный развёрнутый top-10 output, исключён из Git; регенерируется runner. Все известные ранги и агрегаты сохранены отдельно.
- `*_pair_ranks.json` — оценки и два направленных ранга всех 493 авторских пар, включая `different` и `unsure`.
- `*_embeddings.npz`, `*_scores.npy`, `embedding_row_ids.json` — векторы и полные матрицы 493 × 493 в явно заданном порядке.
- `encoding_metadata.json` — длины всех входов и дополнительные диагностические счётчики.
- `verification.json` — независимая сверка матриц с векторами, 1 972 парных оценок и 3 944 направленных рангов, пересчёт метрик и контроль неизменности исходных артефактов.

Матрицы здесь вычисляются полностью: это ограниченный эксперимент, не масштабируемый ANN-пайплайн. Высокие косинусные оценки между моделями не калиброваны как вероятности и не сравниваются по абсолютным величинам.

**Post-hoc проверка ансамбля по сохранённым результатам.** У TF–IDF и MiniLM совпадают 2 ошибки top‑1 в направлении Polymarket → Kalshi и 3 в обратном; объединение их top‑1 даёт 459/461 и 458/461 известных связей против 457/461 и 455/461 у одного TF–IDF. На 461 запрос требуется соответственно 467 и 469 различных кандидатов для следующего этапа (в среднем 1.013 и 1.017; не более двух на запрос). Добавление E5 и BGE к этому объединению даёт **0 дополнительных известных связей**, добавляя ещё 4 и 3 кандидата. Здесь умеренное дополнение лексического поиска MiniLM полезнее расширения до четырёх моделей; это диагностическое наблюдение после получения результатов, а не независимая проверка настроенного ансамбля. Полные пересечения ошибок с внешними ID и счётчики `different` в top‑1 сохранены в `error_overlap.json`; последние не являются false-positive rate классификации. Повторить анализ без inference: `.venv-retrieval/bin/python comparison/retrieval/analyze_error_overlap.py`.
