# Проверенные наблюдения и границы выводов

30 сентября 2026. Независимый пересчёт сохранённых выходов без нового inference. [Проверочный скрипт](verify_findings.py) использует стандартную библиотеку Python; [машиночитаемый результат](verified_findings.json) содержит точные числа, три числовых примера и SHA-256 входов.

## 1. Условная несогласованность NLI: 325 из 839 пороговых пар

Сохранены **1188 уникальных пар и 2376 направленных оценок** DeBERTa-v3-base-mnli-fever-anli. Исходный runner подаёт `title + primary + secondary` и применяет собственное преобразование NLI scores в кандидата отношения. В частности, `exclusion_candidate` получается, если среднее двух contradiction scores ≥0.8 и превосходит оба entailment score минимум на 0.1. [Метод, строки 45–58](../extension/nlp/score_candidate_pool.py#L45), [предсказания](../extension/nlp/corpus_nli_predictions.json), [manifest модели и запуска](../extension/nlp/corpus_run_manifest.json).

Пересечение этих пар с кандидатами одинакового шаблона содержит **839 пар в 19 группах**. Группировка сохраняет event, текст условия с замаскированным порогом, точный secondary, источник и временные поля. В ней **325** пар получили `exclusion_candidate`. Это 38.74% данного условного поднабора, не процент ошибок на всех рынках. [Группировка](../extension/retrieval/experiment.py#L83), [исходный диагностический join](../extension/nlp/conditional_consistency.py), [его сохранённые записи](../extension/nlp/conditional_consistency.json).

Проверка не ограничена чтением счётчиков. Новый скрипт:

- заново получает тип всех 1188 кандидатов из направленных вероятностей;
- независимо извлекает `>`/`>=` и число из `market.primary`, проверяет совпадение непорогового контекста и hashes групп;
- для каждой из 839 пар проверяет `x = max(t_A, t_B) + 1` в **обоих** исходных неравенствах с точной Decimal-арифметикой;
- сверяет множества ID-пар, сохранённые witnesses и флаги конфликтов.

Например, `KXLCPIMAXYOY-27-P6.5` и `KXLCPIMAXYOY-27-P5` имеют предикаты `x≥6.5` и `x≥5`: при `x=7.5` оба истинны. Средний contradiction score — 0.98134. Для `KXCPI-26OCT-T0.4` / `T0.1` оба строгих условия выполняются при `x=1.4`, хотя средний contradiction score — 0.91834.

**Защищаемый вывод:** эвристика NLI→взаимоисключение противоречит совместному YES на 325 парах **в модели общего неограниченного скаляра и бинарной выплаты по указанным правилам**. Это не независимый human-gold error rate, не доказательство неверных фактических резолюций и не сравнение качества всех моделей. 19 повторяющихся групп не дают 839 независимых механизмов. Причиной может быть и несовпадение задачи: NLI между полными предложениями правил не тождественно следованию событий выплат.

## 2. 285/461 — регистронезависимое вхождение строки, не точность retrieval

На 461 паре с авторской меткой `same`:

```python
sum(p['poly_title'].lower() in p['kalshi_title'].lower()
    for p in pairs if p['label'] == 'same')  # 285
```

Получается **285/461 = 61.822%**. Без `.lower()` — **278/461 = 60.304%**. Нормализация NFKC, casefold и пробелов здесь тоже даёт 285, а удаление пунктуации через последовательности `\w+` — уже 296. Поэтому формулу необходимо назвать точно: подстрока без учёта регистра, без границ слов, без добавления event title.

Данные — frozen `redesign/retrieval/reference_pairs.json`, сверенные с `markets.json`; [описание выборки](../redesign/retrieval/REVIEW_RU.md), [первичный audit fixture закреплённой версии](https://github.com/nl2992/prediction-pipeline/blob/f7f652b7ea7c2285fca7c2aa7c02785b11ba9e84/tests/fixtures/endorsed_audit_2026-09-14.json). Полные сторонние fixtures не входят в минимальный Git-пакет; их восстанавливает `python3 scripts/fetch_reference_inputs.py`.

Это показывает значительный готовый лексический сигнал в **отобранной автором** выборке. Подстрока не устанавливает эквивалентность и не доказывает простоту отрицательных примеров. Число нельзя выдавать за Recall@1 либо за свойство всех canonical Polymarket questions: в этом snapshot многие `poly_title` являются короткими вариантами ответа.

## 3. API summary и полные CPI terms добавляют разные условия

У пары `KXCPIYOY-26DEC-T5.0` / `KXLCPIMAXYOY-27-P5` API описывает декабрьское YoY >5% и достижение ≥5% в любом месяце 2026. При одинаковом принятом декабрьском значении первое условие влечёт второе. Но [YOYCPI, с.1–2](https://assets.kalshi.com/contract_terms/YOYCPI.pdf) содержит вычисляемый fallback со степенью **13/12** и поздний предел ожидания в три месяца; [LCPIYOY, с.2](https://assets.kalshi.com/contract_terms/LCPIYOY.pdf) задаёт иную процедуру окончания, включая четырнадцать дней после планового выпуска и исключение для shutdown. Формула и соответствующие страницы дополнительно просмотрены визуально; не предполагается исправление формулы автором анализа.

Ещё одно конкретное расхождение: API secondary октябрьского CPI указывает 8:25 ET, [CPI terms, с.2](https://assets.kalshi.com/contract_terms/CPI.pdf) — 8:29 ET. Числовое включение при одном общем `x` от этого не исчезает. Различия текстов требуют версии документа и применимого scope; **они сами по себе не доказывают реализуемый контрпример к полным выплатам**. Текущий PDF по неизменному URL не считается доказанной исторической редакцией, приоритет API/PDF не установлен. [Подробный аудит](../extension/terms/AUDIT_RU.md), [source manifest](../extension/terms/manifest.json), [структурированные шесть кейсов](../extension/terms/case_audit.json).

## 4. Прямой пример небинарной ветви Kalshi

В сохранённом официальном ответе для [KXTRUMPOUT27-27-DJT](https://external-api.kalshi.com/trade-api/v2/markets/KXTRUMPOUT27-27-DJT), поле `rules_secondary`, уход исключительно вследствие смерти приводит к расчёту на основе последней цены; при её непригодности предусмотрено решение комитета о распределении выплат. Текст сверяется с [политическим входным пакетом](../redesign/cards/political_inputs.json), а происхождение записано в [карточке](../redesign/cards/politics_crossvenue_departure.json).

Этот пункт препятствует **универсальной** модели только из 0/1: правило допускает процедуру, не гарантированно сводящуюся к двум исходам. Он не означает, что конкретная выплата обязательно дробная или что обычные бинарные сценарии невозможно исследовать. Без полного сопоставления действующих условий обеих площадок эквивалентность фактических выплат не удостоверена.
