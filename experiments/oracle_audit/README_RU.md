# Аудит оракула для событийных контрактов

**17 ноября 2026.** На отложенных 668 контрактах правило единогласия разрешило 300, допустило 8 ошибок и отправило 368 на проверку. Это прикладной результат для маршрутизации архивных ответов. В отдельном ретроспективном тесте по CPI официальный выпуск дал 12 из 12 ответов, сверенных с биржей. Эти задачи измеряют разрешение исхода контракта. Для проверки логических отношений между *двумя* контрактами в дипломе требуется отдельная разметка.

## 1. Воспроизведение Kota и проверка доступности сведений

Заново посчитаны голоса во всех 1 189 строках архитектуры A и признаки правильности всех 1 189 строк опубликованной кривой B-final. Код воспроизводит DeepSeek 980/1 189, GPT-column 979, Llama 966, сохранённое большинство A 986 (82,93%), взвешенное голосование A 992 (83,43%), B-final 905 (76,11%). A и B имеют собственные наборы строк. Сравнивать 992 с 905 как парные наблюдения без сопоставления контрактов нельзя. В файлах A колонка называется `gpt4o`, в описании кода указан GPT-5 Nano. CSV не идентифицирует неизменяемую версию модели. Новый запрос в эти три модели не выполнялся. [Статья Kota](https://arxiv.org/abs/2605.30802) · [Код и архив ответов, закреплённая ревизия](https://github.com/Tkota10/Senior-Thesis-Multi-LLM-Resolution/tree/f76754b5bcff1a1d7a50c2f1073a4b6d44bd985c).

Проверены поля **каждого из 486 публичных JSON-пакетов**. В 4 844 элементах sources найден 4 821 пустой text и 23 пустых highlights. Это счёт элементов с возможными повторами URL. У 1 024 элементов (в 348 пакетах) отсутствует дата публикации. У 82 дата позже дня закрытия, включая 28 из 17 пакетов даже после дня закрытия плюс один календарный день UTC. Весь сохранённый кэш собран между 29 января и 23 февраля 2026, после закрытия соответствующих контрактов. Поле даты не устанавливает, что на историческую дату веб-страница содержала тот же текст. Результаты показывают ограничения публичного кэша. Их недостаточно для утверждения, что конкретный агент получил поздний источник в конкретном вызове. Перепроверка доступна по имени и Git blob каждого пакета в [инвентаре](data/evidence_inventory.csv).

**Различия с предыдущей работой команды.** Страница NEW Proposal сообщает 954 / 884 / 878 правильных у A / B до / B после обсуждения на 1 153 общих контрактах и связывает 315 разных пакетов с нумерацией строк в ключе. Закреплённый репозиторий команды при сопоставлении по ID, вопросу, критерию, метке и номеру повтора даёт 1 154 пары, включая 955 верных у A-majority и 879 у B-final. Отдельное сопоставление по row_uid даёт 839 совпадений. Только у 100 общих UID найден файл ожидаемого имени с совпадающим содержанием полей идентичности. Эти числа зависят от фильтра и ключа. Исторические вызовы не привязаны к хешам фактически использованных пакетов, поэтому число 315 сохраняется как заявление proposal. В настоящем аудите B прочитана из построчной кривой итогового раунда. Голоса B первого раунда отдельно не пересчитаны. Прямой запрос к `white-mi/ai_oracle` с доступным подключением вернул 404. [Командный аудит](https://github.com/tarma3v/agentic-oracle-research/blob/2086f45115430ecf0aca6e36e4d5065df43ddea3/audit/audit_results.json) · [Проверка покрытия кэша командой](https://github.com/tarma3v/agentic-oracle-research/blob/2086f45115430ecf0aca6e36e4d5065df43ddea3/audit/cache_coverage.json).

## 2. Новый тест на более поздних сериях

Дату присоединили по нормализованным ID, вопросу, критерию и совпадению метки с каноническим CSV. Для теста взяли серии, у которых все однозначно сопоставленные строки закрылись с 1 октября 2025. До этой даты осталось 455 обучающих строк (291 серия), после — 668 (379 серий). Исключены целиком 33 серии / 66 строк, если серия пересекала границу или дату хотя бы одной строки определить однозначно не удалось. Метки использованы при проверке идентичности архивных строк, обучении и оценке. Модель текста видела только слова вопроса и критерия. Разделение по series ID не гарантирует статистическую независимость тематически близких серий.

| Метод на 668 строках | Верно | Brier |
|---|---:|---:|
| Частота YES на ранних сериях | 425 | 0,2410 |
| Вновь обученный текстовый Naive Bayes без внешних источников | 400 | 0,3805 |
| Среднее трёх преобразованных вероятностей YES | 516 | 0,1471 |
| Веса трёх вероятностей, выбранные на 455 ранних строках | 518 | 0,1434 |
| Взвешенное по confidence голосование Kota | 548 | — |

Для получения P(YES) в двух строках усреднения мы приняли, что confidence относится к выбранному ответу. Для NO берётся 1 − confidence. Таким образом вероятностная сумма может изменить даже ответ агента с confidence < 0,5. В методе Kota confidence суммируется отдельно у проголосовавших YES и NO. Сетка весов по Brier определила 0,4 / 0,3 / 0,3 для GPT-column / DeepSeek / Llama. Индивидуальный GPT-column дал Brier 0,1421, слегка лучше обеих смесей на тесте. Для текстовой модели использовали размеченные только до отсечки контракты, бинарные униграммы и сглаживание Лапласа. Добавление восьми искусственных токенов, кодирующих ответ, меняет 400/668 на 664/668, а инверсия токенов на тесте даёт 10/668. Это положительный контроль чувствительности пайплайна к прямому попаданию метки. Знание исходов внутри весов больших моделей он не диагностирует. [Веса, отбор и агрегаты](results/kota.json) · [Текстовая модель и контроль](results/text_baseline.json).

При единогласии и среднем confidence не ниже **медианы обучающей части 0,9167** на тесте верны 292 из 300 принятых, покрытие 44,91%, accuracy 97,33%. Процентильный bootstrap по 379 series ID (4 000 выборок с возвращением, seed 20261117) даёт интервал точности 95,27–99,02%. Это описательный интервал для данного разбиения. На полном наборе порог статьи 0,91 даёт 551/563 при покрытии 47,35%. Архивные ответы уже использовали ретроспективно собранные источники, поэтому временной тест проверяет перенос порога и весов, а историческую доступность evidence отдельно проверяет тест CPI.

## 3. Время публикации, память процесса и «живой» срез

Берём снимки открытых рынков Kalshi от **28 сентября 2026**, по всем попавшим в них порогам сентябрьского и октябрьского headline и core CPI. Всего 40 контрактов, четыре серии-месяца, два выпуска BLS. Из августовского релиза берётся последнее известное значение. Первые сентябрьский и октябрьский релизы дают эталон по строгому сравнению «выше» и отдельно определяют время видимости результата. Сверка по 12 показанным на четырёх страницах биржи бинарным исходам дала 12/12, из них девять входят в снимок цен. Среди 12 преобладают YES (10). У оставшихся порогов эталон механически выведен из того же официального числа. [Выпуск BLS за август](https://www.bls.gov/news.release/archives/cpi_09112026.htm) · [сентябрь](https://www.bls.gov/news.release/archives/cpi_10142026.htm) · [октябрь](https://www.bls.gov/news.release/archives/cpi_11102026.htm) · [биржевые ссылки и эталоны](data/exchange_labels.json).

| Вес котировки в прогнозе | Верно из 40 | Brier |
|---:|---:|---:|
| 0 (повтор последнего опубликованного значения) | 38 | 0,0500 |
| 0,25 | 38 | 0,0344 |
| 0,50 | 38 | 0,0259 |
| 0,75 | 38 | 0,0245 |
| 1 (середина bid/ask) | 39 | 0,0302 |

Все веса фиксированы для анализа чувствительности. Минимум Brier при 0,75 описывает две даты, оснований выбрать его для эксплуатации недостаточно. Значения котировок — из снимка, а не итоговые цены рынка. Дата выгрузки позднее старта торгов и раньше обоих выпусков; спреды сохранены в [построчных результатах](results/cpi_by_contract.csv).

За одну секунду до официального времени новый процесс вернул DEFER на всех 40 порогах. В момент релиза решил все 40. Замена *будущего* значения сохранила входной пакет побайтно эквивалентным при одинаковой сериализации; замена *доступного* значения перевела ответ с NO на YES на граничном примере. После запуска с известным результатом повторный запуск на предыдущий момент вернул DEFER. Рабочий процесс получает очищенное окружение, только отфильтрованный stdin-пакет и запускается с Python `-I -S`; пробы файлового открытия и создания сокета отклонены Python audit hook, переменная-маркер родителя отсутствует. Это изоляция фиксированного доверенного обработчика. Произвольный код так запускать нельзя. [Код обработчика](worker.py) · [результат теста](results/cpi.json).

17 ноября отдельно записаны три открытых ноябрьских порога и показанные на странице шансы 84%, 46%, 12% для значений выше −0,2%, −0,1%, 0,0%. Это чтение страницы за день, точный момент биржевой котировки неизвестен. По состоянию на этот день обработчик дал три DEFER. Первый выпуск за ноябрь запланирован на 10 декабря. Проспективную точность, цену исполнения и P&L по этим наблюдениям вычислить пока нельзя. ## 4. Что измеряют уверенность, стоимость и время

Архив Nel содержит исходный XML и сохранённую вероятность. В промпте confidence определён как P(YES), а опубликованный парсер инвертирует значение для явного NO. Модели по-разному интерпретируют инструкцию. Для чувствительности метрики оставлены только ID, у которых среди всех подходящих по дате контрактов в контрольном CSV одна возможная метка, есть явный записанный ответ и тег confidence. Повторяющиеся ID могут встречаться несколькими строками. Отбор меняет состав данных. Таблица Brier относится именно к этому подмножеству. Время и расходы справа взяты из архивного полного запуска с 300 заданиями на модель, включая задания без валидного ответа. [Статья Nel](https://arxiv.org/abs/2512.16030) · [Код парсера](https://github.com/LukasNel/kalshibench/blob/d42f8f7201693df723d2eec68e05b39a1f3826af/kalshibench.py) · [полные числители и знаменатели](results/nel.json).

| Модель | Строк для Brier | Сохранённое P | Число из XML как P(YES) | Среднее время, с | USD за 300 заданий по журналу |
|---|---:|---:|---:|---:|---:|
| Claude Opus 4.5 | 221 | 0,2079 | 0,3632 | 11,8 | 11,6336 |
| GPT-5.2-XHigh | 221 | 0,4467 | 0,2383 | 135,7 | 30,3162 |
| DeepSeek V3.2 | 221 | 0,3400 | 0,2493 | 7,9 | 0,3649 |
| Qwen3-235B-Thinking | 221 | 0,3449 | 0,3539 | 25,4 | 1,1882 |
| Kimi-K2 | 213 | 0,3540 | 0,3112 | 16,2 | 0,9358 |

Для Kota сохранено время только 739 из 1 189 строк A, медиана 18,04 с. Журнал не даёт полной фактической стоимости всей связки из трёх провайдеров, поиска и человека. Для протестированного правила средняя стоимость на контракт в условной модели равна **C_авто + (368/668)·C_руч + (8/668)·L**, если ручное решение безошибочно и L — потери от одного пропущенного неверного решения. Отсюда допустимый бюджет автоматизации при сравнении со сплошной ручной проверкой равен (300·C_руч − 8·L)/668. Это порог окупаемости при заданных ценах, без фактического измерения стоимости арбитража.

В отдельном архиве **настоящих вызовов Jev** независимо пересчитан первый из двух повторов по 400 различным примерам маршрутизации франкоязычных обращений. Получено 384/400 (96,0%), на confidence ≥0,95 — 281/289 (97,23%) при покрытии 72,25%. Для всех 800 запросов медиана наблюдавшейся задержки 433 мс, средняя записанная стоимость 0,00001667 USD. Эти цифры относятся к конкретному типу запроса через OpenRouter, региону, модели и дате внешнего замера. Для контрактов подготовлены 60 blind request bodies Jev в пяти режимах: исходный именованный, анонимный, анонимный с обращённым фактом, отсутствие релиза с именем и без него. Reference сохранён отдельно. Ответов Jev для этих 60 запросов пока нет. [Журнал Jev](https://github.com/priorbench/jev/tree/92e0a55586177df869b919b1ec92bb86de2b7329) · [работа о System One](https://arxiv.org/abs/2609.37647) · [официальный контракт Choice](https://docs.typesafe.ai/primitives/choice).

## Повторение

Из корня проекта, Python 3.11+, для основного прогона достаточно стандартной библиотеки.

```bash
cd experiments/oracle_audit
python3 verify.py
```

`verify.py` проверяет SHA-256 входов, затем повторяет анализ архивных ответов, обучение текстовой модели, инвентарь кэша, изолированный replay и генерацию слепых Jev-пакетов. Для пересборки компактных таблиц при доступе к GitHub выполните `python3 prepare.py --fetch`, затем `python3 verify.py`. Для построчной сверки всех 486 исходных JSON используйте `python3 evidence.py --verify-network` или `--verify-directory /path/to/cache/evidence`. Неподтверждённые исторические версии API моделей, неизменяемые логи фактических пакетов, JEV/Exa/OpenAI/Together credentials здесь отсутствуют. Локальная Apple Foundation Model на машине вернула `appleIntelligenceNotEnabled`.

Опциональный `langgraph_demo.py` подключает те же проверенные узлы к StateGraph с ветвями resolve → review/record без кросс-контрактного хранилища. В окружении без пакета langgraph исполнялся базовый обработчик и процессные проверки. Код адаптера прошёл проверку синтаксиса; интеграцию с реальным рантаймом LangGraph и новые сетевые вызовы моделей этот прогон не проверял. [Документация StateGraph](https://docs.langchain.com/oss/python/langgraph/graph-api).
