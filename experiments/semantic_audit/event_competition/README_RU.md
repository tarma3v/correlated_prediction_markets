# Где контекст события меняет первое место

На 292 известных положительных ссылках Polymarket–Kalshi сравнили две задачи. Первая требует найти конкретный контракт среди 493 контрактов целевой площадки. Во второй исследователю заранее известно событие целевого контракта, и алгоритм выбирает между его исходами. Для сравнения использованы те же самые 581 направление поиска из 83 семейств, в которых у целевого события было от 2 до 19 кандидатов. Ещё в 341 направлении у события был единственный кандидат. Внутри него любому методу достаточно просто выбрать этот контракт.

| Модель и пул | Top-1 по заголовку исхода | Top-1 по событию и исходу | Прирост, п.п. | 95% интервал по семействам, п.п. |
|---|---:|---:|---:|---:|
| E5, все кандидаты | 84,96% | 98,55% | +13,59 | [9,01; 18,69] |
| E5, одно целевое событие | 99,10% | 99,40% | +0,30 | [0,00; 0,90] |
| BGE, все кандидаты | 83,30% | 98,15% | +14,85 | [10,06; 20,03] |
| BGE, одно целевое событие | 99,28% | 99,40% | +0,12 | [0,00; 0,36] |

**Результат.** Для E5 наблюдаемый внутрисобытийный прирост меньше заданного порога пяти пунктов. Когда целевое событие известно, заголовки отдельных контрактов уже восстанавливают известные ссылки почти без ошибок. Когда конкурируют все события, контекст приносит дополнительно 13,29 п.п. прироста для E5 (интервал [8,62; 18,55]) и 14,73 п.п. для BGE ([9,98; 19,87]). Простой выбор случайного исхода известного события даёт в среднем 37,67%. В направлении Polymarket → Kalshi добавление контекста дало 0,00 п.п. внутрисобытийного прироста у обеих моделей. В обратном направлении — +0,61 п.п. у E5 и +0,24 у BGE.

**Область вывода.** Полный пул содержит только контракты авторского набора. Событие для условного пула определено по целевой стороне известной ссылки и взято в нормализованном строковом представлении. В развернутом поиске эту информацию пришлось бы предсказать. Метрика засчитывает попадание в конкретный авторский ID. Многие остальные сочетания не размечены. Исследование описывает ретроспективный подбор ссылок в данном корпусе, без независимой проверки смысла договора. Данные двух моделей и двух направлений частично совпадают. Интервалы получены повторными выборками компонент, образованных всеми 493 авторскими парами. Файл результатов содержит списки hashes входов. ## Воспроизведение

Нужны Python 3.10+ и NumPy. В наличии должны быть закреплённые входы авторского набора; их восстанавливает штатный скрипт репозитория. Матрицы обеих моделей уже сохранены. Две последние команды работают офлайн при наличии входных файлов.

```sh
python3 scripts/fetch_reference_inputs.py
python3 experiments/semantic_audit/event_competition/run.py
python3 -m unittest discover -s experiments/semantic_audit/event_competition -v
```

Проверка независимо пересчитывает каждую из 7376 оценок первого места, обрабатывает ничьи и проверяет побайтовый повтор CSV и JSON. Формирование групп использует только заголовки событий. Авторские метки и идентификаторы нужны для проверки целевых ссылок и привязки строк матриц.
