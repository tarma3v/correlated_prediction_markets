# H1: offline acquisition and annotation diagnostic

Это single-venue диагностика поиска и подготовки разметки. **Межплощадочная гипотеза H1 здесь не проверена.** Нет gold-разметки, precision, recall, оценки качества моделей или торговых выводов. Все источники ранее просмотрены; это exploration, не новый holdout.

В `corpus.jsonl` сохранены 323 официальных Kalshi-записи из 29 событий: 286 из первоначального API-снимка, 36 дополнительных записей из official_probe и один политический контракт. Один источник исторический. Снимки сделаны в разные моменты; корпус не представляет одновременно торгуемую вселенную.

Сохранены только ID, event ID, title/subtitle, primary/secondary и provenance. Цены, объёмы, исходы, прежние AI-выводы и авторские метки не используются. Каждая запись указывает исходный файл, JSON locator, URL, время получения и SHA-256. Поля API не гарантируют наличие полного пакета terms, rulebook и действовавших уточнений. Пустое secondary не доказывает отсутствие исключений.

## Фиксированный поиск

- TF-IDF: word 1-2 grams и char_wb 3-5 grams, равный вес, cosine.
- MiniLM: `sentence-transformers/all-MiniLM-L6-v2`, revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, CPU, float32.
- Два входа для каждого метода: `title`; `title + subtitle + primary + secondary`, соединённые переводами строк. Context означает доступные API-поля, не полные договоры.
- Все 323 записи служат запросами. Кандидаты с тем же event_id исключаются **до** top-5. Даты, пороги и источники не используются для жёсткого отсева. Стабильное разрешение равных оценок по ID.
- Никаких сетевых запросов: веса и tokenizer загружаются непосредственно из закреплённого локального snapshot с `local_files_only=True`.

Обработка длинного текста задана заранее: неперекрывающиеся блоки до 254 content tokens плюс специальные токены, attention-mask mean каждого блока, взвешенное числом content tokens среднее блоков и итоговая L2-нормировка. Это явная адаптация представления, не нативный длинноконтекстный MiniLM. В фактическом корпусе максимум 29 токенов для title и 199 для context, поэтому разбиение не понадобилось. Отброшено 0 токенов. Полная статистика каждого входа в `encoding_metadata.json`.

## Очередь разметки

Объединены четыре top-k выдачи и оба направления запроса: 2776 уникальных пар, 83 пары событий. Для отбора используется reciprocal-rank fusion с константой 60. События обходятся циклически в порядке SHA256(seed:event_id), seed 20261021. Не более одной пары контрактов на пару событий и не более шести пар на событие. Политика зафиксирована в коде до inference, не настраивалась по итоговым рангам.

`blind_queue.jsonl` содержит ровно 40 пар из 40 разных пар событий, охватывающих все 29 событий. Порядок пар и ориентация A/B определены хешем. В этом файле нет model scores, ranks, selection reasons, прежних меток или ответов. Все поля разметки пусты. Для независимой разметки выдавайте только этот файл и инструкцию разметки; `selection_audit.jsonl` и `ranks.jsonl` содержат оценки и должны оставаться скрытыми от разметчиков.

Это намеренно разнообразная очередь, не вероятностная выборка. В ней могут быть несвязанные пары, включая результаты вынужденного cross-event top-k для единичных тематик. Количество кандидатов и пересечения методов измеряют объём работы, а не качество. Для будущего recall нужны полностью размеченные ограниченные блоки, включая пары вне выдачи.

## Отдельный Polymarket-инвентарь

`polymarket_text_inventory.jsonl` содержит пять ранее сохранённых текстовых записей с официальных страниц: GTA postponement, GTA release, World Series, NLCS и unemployment. Четыре получены через поисковый индекс, одна через web-render. Это не прямые Gamma/API-снимки; текст может быть устаревшим. Внешние market/condition IDs не подтверждены и оставлены null, локальные aliases явно обозначены. Сохранены только текст правил и provenance, без производных пропозиций, relation labels или editorial summaries. Инвентарь исключён из corpus, retrieval и всех счётчиков кандидатов. Странности исходных формулировок не исправлялись.

## Воспроизведение и проверка

На новом компьютере сначала создайте окружение Python 3.11 и загрузите закреплённую модель. Это скачивание публичных весов, без платного inference:

```bash
python3.11 -m venv .venv-week1-retrieval
.venv-week1-retrieval/bin/python -m pip install -r experiments/week1/h1_queue/requirements.txt
.venv-week1-retrieval/bin/python experiments/week1/h1_queue/download_model.py
.venv-week1-retrieval/bin/python experiments/week1/h1_queue/reproduce.py --output-dir experiments/week1/h1_queue/reruns/local
```

Из корня репозитория, в существующей среде и с заполненным локальным model cache:

```bash
extension/.venv/bin/python -B experiments/week1/h1_queue/verify.py
extension/.venv/bin/python -B experiments/week1/h1_queue/reproduce.py --output-dir experiments/week1/h1_queue/reruns/local
```

`verify.py` читает готовые основные артефакты, проверяет source hashes и точное соответствие полей raw-снимкам, пересчитывает ранги из сохранённых scores, проверяет eligibility до top-k, отсутствие потерянных токенов и чистоту blind queue. Есть граничные проверки chunking и stable ties.

Повторный inference выполняйте в новом `--output-dir` внутри этой папки. Без параметра runner перезаписывает основные результаты. `--freeze-inputs` использовался однократно до окончательного прогона и отказывается перезаписывать существующий lock. Зависимости зафиксированы в `requirements.txt`; фактический запуск выполнен на macOS ARM, CPU. Linux не проверен. При отсутствии исходных snapshots или локальных весов offline-run завершится ошибкой, ничего автоматически не скачивая.

Веса ожидаются в `tmp/hf_cache/models--sentence-transformers--all-MiniLM-L6-v2/snapshots/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/`. Все исходные пути в manifests относительны корню репозитория. `input_lock.json` фиксирует входы; `run_manifest.json` содержит среду, model pin, hashes весов, настройки и hashes результатов. Полные raw-ответы не копируются в эту папку.

Первая техническая проверка выявила неточный JSON locator у pilot wrapper: `markets` вместо `response.markets`. Исправлены только provenance locators и производные hashes, затем выполнен окончательный прогон. Первоначальные lock/manifest сохранены в `development/`; правила отбора и содержательные входы не менялись.
