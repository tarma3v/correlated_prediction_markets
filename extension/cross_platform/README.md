# Один межплощадочный кандидат: core CPI, сентябрь 2026

**Найдена реальная пара контрактов и различие опубликованных исключений. Текущая безусловная связь между выплатами не подтверждена:** правила Polymarket доступны только в индексированной копии официальной страницы, актуальность которой не проверена.

| Площадка | Идентификатор | Условие в обычном сценарии |
|---|---|---|
| Polymarket | public slug `will-core-cpi-yoy-be-2pt3-in-september-2026` | Core CPI YoY за сентябрь 2026 равен 2.3% |
| Kalshi | ticker `KXCPICOREYOY-26SEP-T2.2` | Тот же показатель выше 2.2% |

[Официальный рынок Polymarket](https://polymarket.com/event/core-cpi-yoy-september-2026/will-core-cpi-yoy-be-2pt3-in-september-2026) идентифицирован поисковой выдачей; [страница события](https://polymarket.com/event/core-cpi-yoy-september-2026) при web-open показывает исход 2.3%. Числовой Gamma market ID и conditionId получить не удалось, вместо них не выдумываются значения. [Прямой Kalshi API](https://external-api.kalshi.com/trade-api/v2/markets/KXCPICOREYOY-26SEP-T2.2) вернул HTTP200; исходный ответ сохранён 2026-09-28 в 21:19:45 UTC. Это один дополнительный контракт, не включённый в прежний пилот из 286 рынков.

При общем своевременно опубликованном значении BLS `A: x=2.3 ⇒ B: x>2.2`; обратное неверно — например, при x=2.4. Это математический вывод при совпадении ряда, релиза и остальных условий, а не подтверждённая гарантия контрактов.

**Существенное исключение:** в индексированных правилах Polymarket задержка до следующего запланированного CPI-релиза приводит к использованию предыдущего доступного месяца: “most recent previous month with available data”. У Kalshi secondary rules при задержке из-за shutdown предусмотрено продление до выпуска показателя или срока через шесть месяцев после окончания shutdown. [Polymarket](https://polymarket.com/event/core-cpi-yoy-september-2026), [Kalshi](https://external-api.kalshi.com/trade-api/v2/markets/KXCPICOREYOY-26SEP-T2.2).

Гипотетический контрпример: shutdown задерживает сентябрьскую публикацию дольше срока Polymarket; предыдущий доступный месяц равен 2.3%; позднее сентябрь опубликован как 2.2% в пределах продления Kalshi. При применении полученных условий возможны A=Yes и B=No. **Это сконструированный сценарий, а не наблюдавшиеся значения CPI или фактический исход рынков.** Он показывает, почему нельзя автоматически переносить числовую импликацию на полные правила резолюшена.

## Качество и происхождение evidence

- `kalshi_2pt2.json`: прямой официальный API, exact ticker, полный ответ с primary/secondary и точным UTC-временем.
- `polymarket_indexed_rules.txt`: непрерывный фрагмент условий из search-index официальной страницы. Метаданные поиска указывают crawl примерно двумя неделями ранее. Время записи evidence — 2026-09-28 21:20:07 UTC — **не время обновления исходных правил**.
- `polymarket_indexed_identity.txt`: точный публичный market URL из той же выдачи.
- `polymarket_current_page_render.txt`: нынешний текстовый web-render события. Исходы видны, тело Rules скрыто. AI-generated Market Context не использовался как правило.
- `polymarket_exact_market_failure.txt`, `probe_manifest.json`: timeout web-open конкретного рынка и три reset при прямых HTTP-запросах официального сайта.
- `pair.json`: структурированная пара, assumptions, исключения, контрпример и ограничения. `manifest.json`: hashes evidence.

Всего выполнено **9 логических публичных запросов**, после чего сбор остановлен: 4 прямых HTTP, 3 поисковых запроса и 2 web-open. Полный HTML с `__NEXT_DATA__` не получен. Пакет нельзя описывать как успешную API-выгрузку Polymarket, снимок всей действующей спецификации или валидацию эквивалентности между площадками. Полные Kalshi contract terms также ещё не проверены.

## Воспроизведение

```bash
python3 build_pair.py
```

Команда офлайн пересобирает `pair.json` из сохранённых доказательств и проверяет наличие основных фрагментов. `probe.py` повторяет только три первоначальные HTTP-попытки; сетевой результат может измениться. Поисковый индекс не заменяет архивирование версий правил.

Исследовательская ценность примера — конкретная необходимость моделировать **правила при задержке данных** и хранить источник/версию текста. Для финальной разметки требуется повторно открыть актуальные Rules, получить идентификаторы контрактов и сверить полные исключения обеих площадок. До этого: `conditional_relation + abstain_on_unconditional_contract_claim`.
